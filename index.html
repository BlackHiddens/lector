Comment ça marche & limites (à lire une fois)
  • Un navigateur ne peut pas faire de vrai ping (ICMP). Le test consiste à ouvrir une connexion web vers l'adresse : si l'appareil répond sur ce port, il est marqué « Répond ».
  • Un appareil allumé mais sans page web sur le port testé apparaîtra « Sans réponse ». Ajuste le port si besoin.
  • Ce que l'app récupère toute seule (maximum autorisé au navigateur) : statut, latence (dernière + moyenne), disponibilité %, dernière fois vu, icône/favicon, et les services web ouverts (ports http/https) via Analyser tout ou la case sonde auto.
  • Ce qui reste impossible depuis le navigateur (règle de sécurité CORS) : lire le titre de la page, l'en-tête Server, la MAC et le port de switch. Ces infos-là ne sont accessibles qu'avec l'analyseur local (ci-dessous).
  • Pour une vraie identification automatique (titre, en-tête Server, type de serveur embarqué), utilise l'analyseur local fourni à part : il génère un JSON que tu réinjectes ici via Importer (les libellés se remplissent tout seuls, sans doublon).
  • Champ Notes (bouton ✎) : pour tes infos manuelles — port du switch, emplacement, n° de série. Conservé à l'export/import.
  • Enregistrer / partager : le bouton 💾 Enregistrer télécharge un fichier .html autonome contenant tes données (libellés, notes, ports de switch, ordre). Envoie ce fichier à un collègue : il l'ouvre déjà rempli. Une * sur le bouton = modifications non enregistrées.
  • Ordre : glisse une ligne par la poignée ⠿ pour la déplacer. Par défaut la liste est triée par IP ; le bouton ↕ Trier par IP réordonne à tout moment.
  • Pendant que tu travailles, l'app mémorise aussi dans ton navigateur (localStorage) — rien n'est envoyé sur Internet. Pour une copie sûre et partageable, utilise 💾 Enregistrer.
  • Pour surveiller un réseau local en http, ouvre ce fichier en local (double-clic), pas via une adresse https.
